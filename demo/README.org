* Demo Recording

=img/demo.gif= is recorded from a real Emacs, without a screen
recorder: =demo.el= drives a scripted session and captures one frame
per tenth of a second through =x-export-frames=.

#+begin_src shell
  Xvfb :99 -screen 0 1280x900x24 &   # when there is no display
  DISPLAY=:99 emacs -Q -l demo.el    # writes frames to /tmp/demo-wb
#+end_src

Build the animation from the frames, at their own size and without
dithering:

#+begin_src shell
  ffmpeg -framerate 13 -start_number 1 -i frames/f%04d.png \
      -filter_complex "[0:v]tpad=stop_mode=clone:stop_duration=2,\
                       split[a][b];[a]palettegen=max_colors=256[p];\
                       [b][p]paletteuse=dither=none" \
      -loop 0 raw.gif
  gifsicle -O3 raw.gif -o ../img/demo.gif
#+end_src

Three rules, each one measured against the source frames:

- No scaling.  The box is one pixel wide, and a resize turns that
  line into two grey ones: the edge column reads 127 in the frame and
  178 after =scale=820=.
- No dithering and no =--lossy=.  Both scatter noise over flat
  colours, and the file gets /bigger/: 80K dithered and lossy against
  47K clean.  Decoded back, the lines the package draws come out
  column for column; what the 256 colour palette costs is at most
  five levels on antialiased text.
- No frame rate resampling.  The =fps= filter drops frames unevenly
  and the motion stutters.

Record at a width the reader will not scale either; 840 fits the
column GitHub renders the README in.

* Screenshots

=shots.el= draws the graphic ones the same way, one frame each:

#+begin_src shell
  DISPLAY=:99 emacs -Q -l shots.el   # writes ../img/encloses-gui.png
                                     # and ../img/windows-gui.png
#+end_src

=img/screenshot.png= comes from =make gui= in the top directory,
which exports the frame it measures.

The terminal one is not a photograph of a terminal.  =shots.py= runs
Emacs in a pseudo terminal, feeds the byte stream into a [[https://github.com/selectel/pyte][pyte]] screen —
the same way =make tty= checks the terminal box — and paints the
screen it reports, cell by cell, into a PNG:

#+begin_src shell
  python3 shots.py shots-tty.el ../img/encloses-tty.png
#+end_src

The recordings draw the box in a colour, through
=window-box-color=.  The default is the grey of the =window-box=
face, which is what the package draws and what a one pixel line
should look like next to your text — and next to invisible in a
picture the reader looks at once.

The terminal box is checked without eyes: =make tty= in the top
directory runs Emacs in a pseudo terminal and reads the screen back
through pyte.
