** About The Project

=window-box-mode= draws a rectangular box around every window that
shows the buffer.  Nothing more: what your header line and your mode
line say stays yours, and the box only decides whether they are
inside it or outside.  It works on graphic displays and in the
terminal.

[[file:img/demo.gif]]

Two side windows boxed, on a graphic display; the frame comes from
=make gui=, which also measures it:

*** How It Works

On a graphic display the box is one pixel wide on every side: the
side edges are one pixel fringes, which run the full window height,
and the horizontal edges are one pixel rows or an overline.  One
pixel throughout, because an overline is always one pixel and the
rest matches it.  In a terminal the box is made of box-drawing
characters, with the sides in one-column margins along the lines of
text.

=make gui= proves the pixels: it exports a frame with two boxed side
windows and reads the edges back with pillow, checking that each one
is exactly one pixel and sits on the window's edge.

By default the horizontal edges attach to the lines the window
already has: the top edge is an overline on the header line, the
bottom edge an overline on the mode line.  Attaching gives the box
the border role of the line: its own underline and box give way,
while content, fonts and colors stay yours.  The side edges span the
window body; on the header and mode line rows the closure belongs to
the row itself, for example through a colored glyph at each end — a
box border there is drawn or clipped at the display engine's whim, so
the package does not pretend to own it.  Set
=window-box-attached-edges= to nil for edges as thin rows of their
own, which the package does own in full; where a window has no header
or mode line, a row is drawn either way.

The side edges of the rows the box takes in are its own work: a one
pixel bar at each end on a graphic display, the vertical edge or a
corner in a terminal.  The box puts them on the row through the
window parameter and takes the row back off it when the mode goes, so
what the row says is untouched.

Only window dressing is used:

- A row of the box's own lives in the window's tab line or mode line
  parameter, so the buffer's own =tab-line-format= and
  =mode-line-format= are not touched, and only where the window is
  not using that row itself.  A row the box takes in keeps what it
  shows and gets the box's ends around it, through the same window
  parameters.  Everything goes back as it was when the mode turns
  off.
- The terminal side edges are glyphs in one-column margins, hung on
  the buffer's =line-prefix=.  A prefix reaches the empty rows below
  the last line, where an overlay would stop and leave the box open,
  and a glyph bound for a margin stays invisible in a window that has
  none — so the sides show in the boxed windows and nowhere else.
  The buffer's own prefix comes back when the mode turns off.
- A window whose margins are wider than the one column a side glyph
  needs keeps them, and gets the top and bottom edges alone.  Magit's
  log writes the author and the date into a thirty column right
  margin, and a box that took that column would drop them without a
  word.  The buffer is asked as well as the window, and any width it
  asks for counts: Emacs applies =left-margin-width= when a buffer is
  displayed, so a mode that asks later — outline drawing its fold
  buttons in the margin — would never be seen once the box has
  written its own width into the window, and one column is all a fold
  arrow needs.  The box gives the window back its own width when it
  steps aside, unless someone else has set one since.  Only in a
  terminal: on a graphic display the sides are fringes and the
  margins are never touched.

Other packages dress windows too, and a side window rule that sets
its parameters on every display would strip the box off again.  So
the box listens for window changes and puts back what went missing,
writing only what differs.

*** What the Box Encloses

A window is a stack of rows: the tab line, the header line, the text,
the mode line.  =window-box-encloses= says which of them the box holds
besides the text — all three by default, so the box is drawn around
the whole window.

#+begin_src emacs-lisp
  ;; the whole window, which is the default
  (setq window-box-encloses '(tab-line header-line mode-line))

  ;; the text alone
  (setq window-box-encloses nil)

  ;; the header line inside, the mode line outside
  (setq window-box-encloses '(header-line))
#+end_src

It is buffer-local where you set it that way, so one buffer can be
boxed around everything and another around its text alone.

[[file:img/encloses-gui.png]]

Four windows, one setting each; the box is drawn in a color here so
the edges are easy to find.  The edge above a row is that row's
overline and the edge below it its underline, both one pixel at the
row's very edge, and =make gui= measures every one of them against
the row heights Emacs reports.

In a terminal the box is characters, and a character needs a row:

[[file:img/encloses-tty.png]]

The top edge takes the tab line row while the window is not using it,
and the row that ends the box carries the corners, since there is no
row below the mode line.  Where an edge has nowhere to go — a window
whose rows the box leaves outside, or one that shows its own tabs —
the box is drawn on the sides it can reach.

** Getting Started

Install and turn the mode on in the buffers you want boxed:

#+begin_src emacs-lisp
  (use-package window-box
    :ensure t)

  ;; for example: a box around every help buffer
  (add-hook 'help-mode-hook #'window-box-mode)
#+end_src

It pairs well with [[https://github.com/MArpogaus/auto-side-windows][auto-side-windows]]: box what lands in a side
window, and the frame reads as panels.

#+begin_src emacs-lisp
  (add-hook 'auto-side-windows-after-display-hook
            (lambda (buffer &rest _)
              (with-current-buffer buffer (window-box-mode 1))))

  ;; The mode is the buffer's, and a help buffer turns up in a panel
  ;; and in an ordinary window at once.  A box belongs to the place:
  (setq window-box-window-predicate
        (lambda (window) (window-parameter window 'window-side)))
#+end_src

** Customization

There is little of it, on purpose:

| Option                       | Meaning                                        |
|------------------------------+------------------------------------------------|
| =window-box=                 | face of the box; its foreground is the color   |
| =window-box-color=           | one color override, buffer-local for per-buffer |
| =window-box-encloses=        | which of the window's rows are inside the box  |
| =window-box-attached-edges=  | edges on the rows you have, or rows of their own |
| =window-box-characters=      | the glyphs of the terminal box                 |
| =window-box-window-predicate= | which windows of a boxed buffer get the box    |

Everything else is deliberately absent: the box has one thickness,
one pixel, because an overline cannot be thicker.

A box color per buffer:

#+begin_src emacs-lisp
  (setq-local window-box-color "orange")
  (window-box-mode 1)
#+end_src

Rounded corners in the terminal, for example:

#+begin_src emacs-lisp
  (setq window-box-characters "╭╮╰╯│─")
#+end_src

** In the Terminal

The box is drawn from characters, so it works in =emacs -nw=.  The
test suite proves it: =make tty= runs Emacs in a pseudo terminal,
boxes two windows side by side, and reads the screen back through
[[https://github.com/selectel/pyte][pyte]], failing on any edge that never closes its corner:

#+begin_example
  ┌──────────────────────────────────────────────┐
  │boxed in the terminal                         │
  │second line                                   │
  └──────────────────────────────────────────────┘
#+end_example

A window that shows a header line still gets a row of the box's own
above it: a terminal has no overline to mark the header with, so the
box draws its top edge in the tab line row instead.  With the header
inside the box it gets the vertical edges at its ends as well, and
the mode line, having no row below it to put an edge in, carries the
corners and closes the box itself:

#+begin_example
  ┌──────────────────────────────────────────────┐
  │ a header line of my own                      │
  │boxed around its own rows                     │
  │                                              │
  └ a mode line of my own                        ┘
#+end_example

Both screens come from =make tty=, which asserts them.

** Known Limits

- In a terminal the side edges run along lines of text, so they stop
  where the buffer ends.  On graphic displays the fringes run the full
  window height.
- In a terminal an edge needs a row of its own, and there are only so
  many: the top edge takes the tab line row while the window is not
  using it, and there is no row below the mode line at all.  So a row
  that ends the box carries the corners instead of an edge, and where
  the box would have to draw between two rows — a header line left
  outside — there is no edge on that side.  A graphic display draws
  every combination.
- A row the box takes in shows the box's ends where its own content
  would otherwise begin, so a row that fills its width to the last
  column loses that column to the edge.
- The box color of the fringes is buffer wide, because face remaps
  are: fringe indicators such as continuation arrows draw on the box
  color.
- A window that shows its own tab line keeps it, inside the box or
  outside as =window-box-encloses= says.  In a terminal the tabs take
  the row the top edge would have used, so such a window is boxed on
  three sides and its tab line closes it at the top.
- A scroll bar sits outside the fringe, so the right edge lands
  inside it.  Turn the scroll bar off for a clean box.
- The box narrows the window's fringes to its own width, so with the
  default eight pixel fringes the text shifts by seven the moment a
  box appears.  =(fringe-mode 1)= leaves the text where it is.
- An attached edge costs the line it hangs on one pixel of height, so
  the body moves down by one when the box appears.  That is the price
  of a box: it has to occupy a pixel somewhere, and an unattached edge
  takes a whole row instead.

** Comparison with buffer-box

The mechanism follows Nicolas Rougier's [[https://github.com/rougier/buffer-box][buffer-box]], which draws its
borders from the tab line, the margins and the mode line.  The
differences are deliberate:

- buffer-box replaces the header line and the mode line with its own;
  window-box leaves what they say to you and only draws its edges
  around them, or between them and the text.
- buffer-box attaches the side edges to the buffer with overlays, so
  they stop at the end of the text; window-box hangs the terminal
  sides on the buffer's =line-prefix=, which reaches the empty rows
  below the last line as well, and a glyph bound for a margin stays
  invisible in a window that has none.  On graphic displays the sides
  are fringes, which run the full window height.
- buffer-box zeroes the frame fringes and advises =set-window-margins=
  and =set-window-fringes=; window-box changes nothing global.
- buffer-box offers border styles and a rich header; window-box draws
  a box.
