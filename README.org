** About The Project

=window-box-mode= draws a rectangular box around every window that
shows the buffer.  Nothing more: the mode line and the header line
stay whatever you made them.  It works on graphic displays and in the
terminal.

[[file:img/demo.gif]]

Two side windows boxed, on a graphic display; the frame comes from
=make gui=, which also measures it:

[[file:img/screenshot.png]]

*** How It Works

On a graphic display the box is one pixel wide on every side: the
side edges are one pixel fringes, which run the full window height,
and the horizontal edges are one pixel rows or an overline.  One
pixel throughout, because an overline is always one pixel and the
rest matches it.  In a terminal the box is made of box-drawing
characters, with the sides in one-column margins along the lines of
text.

=make gui= proves the pixels: it exports a frame with two boxed side
windows and reads the edges back with pillow, checking that each one
is exactly one pixel and sits on the window's edge.

By default the horizontal edges attach to the lines the window
already has: the top edge is an overline on the header line, the
bottom edge an overline on the mode line.  Attaching gives the box
the border role of the line: its own underline and box give way,
while content, fonts and colors stay yours.  The side edges span the
window body; on the header and mode line rows the closure belongs to
the row itself, for example through a colored glyph at each end — a
box border there is drawn or clipped at the display engine's whim, so
the package does not pretend to own it.  Set
=window-box-attached-edges= to nil for edges as thin rows of their
own, which the package does own in full; where a window has no header
or mode line, a row is drawn either way.

The rule is the same at the top and at the bottom: a line the window
already shows is the edge, and only where it shows none does the box
draw a row of its own.  In a terminal that is all there is to it,
since a terminal has no overline: a header line is the top boundary,
a mode line the bottom one.

Only window dressing is used:

- A drawn top edge lives in the window's tab line, set through the
  window parameter, so the buffer's own =tab-line-format= is not
  touched; a drawn bottom edge uses the mode line parameter of a
  window that shows no mode line, and puts the old state back when
  the mode turns off.
- The terminal side edges hang on an overlay that carries the
  =window= property.  Each window gets its own, so one buffer shown in
  two windows works.

** Getting Started

Install and turn the mode on in the buffers you want boxed:

#+begin_src emacs-lisp
  (use-package window-box
    :ensure t)

  ;; for example: a box around every help buffer
  (add-hook 'help-mode-hook #'window-box-mode)
#+end_src

It pairs well with [[https://github.com/MArpogaus/auto-side-windows][auto-side-windows]]: box what lands in a side
window, and the frame reads as panels.

#+begin_src emacs-lisp
  (add-hook 'auto-side-windows-after-display-hook
            (lambda (buffer &rest _)
              (with-current-buffer buffer (window-box-mode 1))))
#+end_src

** Customization

There is little of it, on purpose:

| Option                       | Meaning                                        |
|------------------------------+------------------------------------------------|
| =window-box=                 | face of the box; its foreground is the color   |
| =window-box-color=           | one color override, buffer-local for per-buffer |
| =window-box-attached-edges=  | overlines on your lines, or rows of their own  |
| =window-box-characters=      | the glyphs of the terminal box                 |

Everything else is deliberately absent: the box has one thickness,
one pixel, because an overline cannot be thicker.

A box color per buffer:

#+begin_src emacs-lisp
  (setq-local window-box-color "orange")
  (window-box-mode 1)
#+end_src

Rounded corners in the terminal, for example:

#+begin_src emacs-lisp
  (setq window-box-characters "╭╮╰╯│─")
#+end_src

** In the Terminal

The box is drawn from characters, so it works in =emacs -nw=.  The
test suite proves it: =make tty= runs Emacs in a pseudo terminal,
boxes two windows side by side, and reads the screen back through
[[https://github.com/selectel/pyte][pyte]], failing on any edge that never closes its corner:

#+begin_example
  ┌──────────────────────────────────────────────┐
  │boxed in the terminal                         │
  │second line                                   │
  └──────────────────────────────────────────────┘
#+end_example

A window that shows a header line has no row of its own above it:
the header is the top boundary, since a terminal has no overline.

** Known Limits

- In a terminal the side edges run along lines of text, so they stop
  where the buffer ends.  On graphic displays the fringes run the full
  window height.
- A header or mode line row reaches past the side edges, which belong
  to the body.  Closing such a row at its ends is the row's own
  business: a glyph at each end does it, and the demo shows one.
- The box color of the fringes is buffer wide, because face remaps
  are: fringe indicators such as continuation arrows draw on the box
  color.
- A window whose buffer shows its own tab line loses it to the top
  edge while the box is on, unless the window also shows a header
  line, which the box then uses instead.
- A scroll bar sits outside the fringe, so the right edge lands
  inside it.  Turn the scroll bar off for a clean box.
- The box narrows the window's fringes to its own width, so with the
  default eight pixel fringes the text shifts by seven the moment a
  box appears.  =(fringe-mode 1)= makes boxing cost no layout change.

** Comparison with buffer-box

The mechanism follows Nicolas Rougier's [[https://github.com/rougier/buffer-box][buffer-box]], which draws its
borders from the tab line, the margins and the mode line.  The
differences are deliberate:

- buffer-box replaces the header line and the mode line with its own;
  window-box leaves both to you.
- buffer-box attaches the side edges to the buffer, so one buffer in
  two windows shares them, and they stop at the end of the text;
  window-box binds the terminal sides to the window through the
  overlay =window= property, and on graphic displays uses fringes,
  which run the full window height.
- buffer-box zeroes the frame fringes and advises =set-window-margins=
  and =set-window-fringes=; window-box changes nothing global.
- buffer-box offers border styles and a rich header; window-box draws
  a box.
